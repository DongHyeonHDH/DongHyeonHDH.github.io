## 프로젝트 운영 관점에서 확인한 과제

통합 프로젝트를 준비하며 구현할 기능과 배포·운영에 필요한 항목을 함께 정리했다. 백엔드 모니터링 대시보드 구축과 개선, 서버 배포와 운영, 빌드·배포 자동화가 필요하다. 초기 단계부터 이런 운영 요소를 고려해야 한다.

## 기능과 역할 분류

현재 도메인 후보는 사용자, 카테고리, 게시글, 댓글, 요청, 검색이다. 댓글이 게시글과 요청을 모두 참조할 수 있다면 어느 도메인에 둘지 추가로 결정해야 한다.

회원 기능에서는 회원가입과 로그인 페이지를 구축하고 OAuth 2.0 도입 여부를 검토한다. 테스트 데이터는 이름 앞에 `TEST_`를 붙여 이후 `LIKE` 문으로 쉽게 찾고 삭제할 수 있도록 한다.

카테고리는 세부 카테고리를 두고, 나머지 분류는 태그로 구현한다. 왼쪽 사이드바에는 카테고리 탐색 기능을 둔다. 태그는 게시글 위에 fragment로 삽입하고, 태그별 이동과 검색 결과 페이지의 페이징을 구현한다.

## 게시글과 검색

게시글 CRUD와 태그 기능을 먼저 구현한다. 태그 기반 검색의 정렬 방식은 게시글 하나에 허용할 태그 수에 따라 달라질 수 있다.

- 여러 태그를 허용한다면 TF-IDF 기반 정렬을 검토한다.
- 태그를 세 개 이하로 제한한다면 검색 결과의 우선순위를 별도로 정의한다.

마이페이지에는 사용자가 작성한 게시글을 보여주고, 이후 파일 업로드를 위한 DB 작업과 코드를 추가한다. 요청 게시글과 관리자 페이지도 구현한다. 관리자는 높은 권한을 가지므로 관리자에게만 삭제 기능을 허용한다.

## 배포와 모니터링

서버를 실제로 배포하고 운영할 수 있어야 하며 빌드와 배포 자동화가 필요하다. 프로젝트가 확장되면 다른 로컬 환경에 ELK Stack을 도입해 로그 모니터링 시스템을 구성하는 방안을 검토한다. Redis를 이용한 JWT 토큰 관리도 추후 검토 항목이다.

## 배운 점

통합 프로젝트에서 백엔드의 역할은 API 구현에만 머물지 않는다. 도메인 경계, 권한, 테스트 데이터 관리, 검색 정책부터 배포 자동화와 모니터링까지 초기에 정리해야 한다. OAuth 2.0, 태그 수 제한, 댓글의 도메인 소속, Redis 도입 여부는 구현 전에 팀이 합의해야 할 항목으로 남았다.
